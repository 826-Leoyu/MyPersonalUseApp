## Problem Statement

我需要每天规划要做的事。现有的待办 App 大多是一条竖着的列表，排序靠上下拖动，没法表达"这件事做完接哪件""这几件事是一组"这种关系；白板类 App（Freeform、Miro）虽然自由，但它们不是为"每天的任务"设计的：没有按日期分页，没有"完成"的概念，没做完的事也不会自动带到第二天。

我想要一个像 Apple 备忘录一样干净的界面，但每天是一张可以随意摆放任务卡片的纸，卡片之间可以连线，做完就拖走，没做完的第二天自动出现。这个 App 只给我自己用，要能在 Windows 电脑和 Android 手机上用，以后也要能装到 iPhone 上。

## Solution

一个用 Flutter 写的跨平台 App：

- **每天一页画布**：灰白背景、白色内容区，任务是淡黄色（可换色）的圆角卡片，可以放在任意位置，可以平移、缩放画布。
- **碰撞连线**：把一张卡片拖到另一张上停留约 0.4 秒，出现预览，松手后就连上一条平滑的带箭头曲线。断开连线有两种方式：再碰撞一次，或者点击连线后点 ✂️。
- **拖走完成或删除**：拖动卡片时底部出现 ✅ 完成区和 🗑️ 回收站区；双击卡片也能快速完成。完成的卡片保留历史记录，删除的卡片在回收站保留 10 天。
- **自动顺延**：没完成的任务在之后第一次打开 App 时，自动搬到当天画布的左上角，并标上"顺延"；原来那天只留下一条只读的历史记录，所以任何时候都不会有重复的有效任务。
- **日期导航**：左侧的日期列表可以切换日期，也可以提前规划以后的日子。窗口窄时它是收起的抽屉，窗口宽时是常驻、可以折叠的侧栏；Windows 和 Android 用同一套界面，只按页面宽度切换（v4）。日期统一用英文月份缩写显示，例如 `Tue, Oct 20, 2026`。过去的日期只能查看，不能新建卡片。
- **Windows 快捷键**：常用操作都有快捷键，并且支持 Ctrl+Z 撤销。
- 第一版数据只存在本机，数据结构按以后能用 Supabase 同步来设计。

## User Stories

> 编号保持 v1 不变，方便对照；v2 / v3 修改过的条目标记为 **（v2 修改）** / **（v3 修改）**，新增的条目从 72 开始。

### 画布与日期
1. 作为用户，我希望打开 App 时直接看到今天的画布，这样不用多点一下就能开始规划。
2. 作为用户，我希望每天有一张独立的画布，这样不同日期的任务不会混在一起。
3. 作为用户，我希望顶部显示当前日期，格式是 `Tue, Oct 20, 2026`，这样我不会在错误的日期上安排任务。**（v3 修改）**
4. 作为用户，我希望从左边缘滑出（或点左上角的日历按钮打开）日期抽屉，按周翻看并选择日期，平时它收起来不占画布的地方。
5. 作为用户，我希望有一个"今天"按钮，看别的日期时能一键回到今天。
6. 作为用户，我希望能切换到未来任意一天并添加任务，这样可以提前规划。
7. 作为用户，我希望能切换到过去的日期，看当天完成了什么、哪些任务被顺延走了；过去的日期只能查看，不能新建卡片。**（v3 修改）**
8. 作为用户，我希望日期抽屉里能看到每天还有几个没完成的任务，这样能一眼知道哪天比较满。
9. 作为用户，我希望在画布空白处拖动就是平移画布，这样在大画布上能自由移动。
10. 作为用户，我希望用双指捏合缩放画布，这样卡片多的时候可以缩小看全局。
11. 作为 Windows 用户，我希望用 Ctrl + 鼠标滚轮缩放、在空白处拖动鼠标平移，这样用鼠标也顺手。
12. 作为用户，我希望画布背景干净、没有点阵（灰白底、白色内容区，见 `docs/ui/`），这样看起来清爽。**（v4 修改）**
13. 作为用户，我希望滑动画布永远不会意外切换日期，这样拖动卡片时不会跳到别的日子。

### 卡片的创建与编辑
14. 作为用户，我希望双击画布空白处就能在那个位置新建一张卡片并直接输入标题，这样记任务很快。
15. 作为用户，我希望有一个"＋"按钮，在当前可视区域的中间新建卡片，这样单手操作也方便。
16. 作为用户，我希望新卡片默认是淡黄色圆角，这样不用每次挑颜色。
17. 作为用户，我希望新建卡片时如果标题是空的就自动丢弃，这样不会留下空白卡片。
18. 作为用户，我希望点一下卡片就选中它，再点一下已选中的卡片就能编辑标题和备注，这样选中和编辑都很顺手。**（v2 修改）**
19. 作为用户，我希望备注是可选的，卡片上在标题下面只显示备注的第一行，超出部分用省略号，这样画布不会太乱。**（v2 修改）**
20. 作为用户，我希望按住卡片拖动就能移动它，这样可以随意摆放。
21. 作为用户，我希望正在拖动的卡片显示在最上层，这样不会被其他卡片挡住。
22. 作为用户，我希望选中卡片后可以拖右下角的手柄来调整大小，这样内容多的卡片可以放大。
23. 作为用户，我希望卡片大小有上下限，这样不会被缩到看不见或者大到盖住整个画布。
24. 作为用户，我希望长按卡片（Windows 上右键）会弹出菜单，里面有改颜色、编辑、删除。
25. 作为用户，我希望从 8 种柔和的预设颜色里给卡片选色，这样可以按类别区分任务。
26. 作为用户，我希望有"自定义"调色盘可以选任意颜色，这样不受预设限制。
27. 作为用户，我希望卡片文字根据背景颜色深浅自动变黑或变白，这样选了深色也看得清。
28. 作为用户，我希望所有改动（移动、改名、改色、改大小）都自动保存，这样关掉 App 也不会丢。

### 碰撞连线
29. 作为用户，我希望把一张卡片拖到另一张上停留一会儿就能连线，这样不用找连线按钮或小圆点。
30. 作为用户，我希望拖动时只是路过其他卡片不会触发连线，这样摆放卡片时不会连错。
31. 作为用户，我希望停留时间到了以后，目标卡片轻微放大并发光，同时出现一条虚线预览，这样我知道松手会连上。
32. 作为用户，我希望两张已经连着的卡片再碰撞时显示 ✂️ 预览，这样我知道松手会断开。
33. 作为用户，我希望出现预览后把卡片移开就取消操作，这样反悔不需要额外步骤。
34. 作为用户，我希望松手后手机轻微振动一下，这样确认操作已经生效。
35. 作为用户，我希望连线或断开后，被拖的卡片自动弹回原来的位置，这样我摆好的布局不会被打乱。
36. 作为用户，我希望连线带一个细箭头，从被拖的卡片指向被碰的卡片，这样能看出先后顺序。
37. 作为用户，我希望一张卡片可以连多条线（分叉、汇合），这样能表达复杂一点的安排。
38. 作为用户，我希望线是平滑的曲线，自动从两张卡片最近的边连出去，这样看起来干净。
39. 作为用户，我希望移动卡片时连线实时跟着弯曲，这样任何时候连线都是对的。
40. 作为用户，我希望新建连线时有"画出来"的动画、断开时线淡出，这样操作有反馈、看着舒服。
41. 作为未来的用户，我希望现在连的线已经记录了方向，这样以后加"依赖关系"和"时间轴"时不用重新连。

### 完成
42. 作为用户，我希望拖动卡片时屏幕底部出现 ✅ 完成区和 🗑️ 回收站区，这样完成和删除都只需一个拖动。
43. 作为用户，我希望把卡片拖进 ✅ 区后它打勾消失，这样画布上只剩没做完的事。
44. 作为用户，我希望双击卡片就能快速完成它，这样不用拖到底部。
45. 作为用户，我希望完成的任务保留在当天的"已完成"列表里，这样能回顾自己做了什么。
46. 作为用户，我希望能打开某一天的"已完成"列表并看到完成数量，这样有成就感。
47. 作为用户，我希望可以撤销误点的完成（在"已完成"列表里取消完成）：卡片在今天或未来时回到原来的位置；在过去的日期时直接顺延到今天，原日期留下历史记录。**（v3 修改）**
48. 作为用户，我希望已完成卡片相关的连线在画布上隐藏，取消完成后再恢复显示。
49. 作为未来的用户，我希望完成记录包含完成时间，这样以后可以做统计。

### 删除与回收站
50. 作为用户，我希望把卡片拖进 🗑️ 区就把它移到回收站，这样不想做的任务可以快速清掉。
51. 作为用户，我希望删除后底部出现几秒的"撤销"提示，这样误删可以马上恢复。
52. 作为用户，我希望删除的卡片在回收站保留 10 天，这样过几天后悔了还能找回来。
53. 作为用户，我希望回收站里每张卡片显示还剩几天会被永久删除。
54. 作为用户，我希望能从回收站恢复卡片：原日期是今天或未来时，回到原来的日期和位置；原日期已经过去时，直接顺延到今天，原日期留下历史记录。**（v3 修改）**
55. 作为用户，我希望恢复卡片时，如果原来连着的卡片还在，连线也一起回来。
56. 作为用户，我希望能在回收站里立即永久删除某一张，或者一键清空（都要先确认）。
57. 作为用户，我希望超过 10 天的卡片自动永久删除，这样回收站不会越积越多。

### 顺延
58. 作为用户，我希望昨天没完成的任务在今天第一次打开 App 时自动出现在今天的画布上，这样不会漏事。
59. 作为用户，我希望顺延过来的卡片放在今天画布的左上角，并保持它们原来的相对位置和连线，这样之前的安排还在。
60. 作为用户，我希望今天已有的卡片自动往右移，给顺延的卡片腾位置，这样不会互相重叠。
61. 作为用户，我希望顺延的卡片带一个"顺延"标记，这样知道哪些是拖下来的。
62. 作为用户，我希望连续几天没打开 App 时，之前所有没完成的任务都顺延到今天，这样一次就收拾干净。
63. 作为用户，我希望未来日期上提前规划的任务不受顺延影响。
64. 作为用户，我希望同一天多次打开 App 不会重复顺延，这样卡片不会被搬来搬去。

## Implementation Decisions

### 架构总览

分四层，依赖方向只能从上往下：

1. **界面层（Board UI）**：日期抽屉、画布、卡片、历史记录、连线绘制、底部投放区、已完成列表、回收站页面、颜色选择器。
2. **界面状态层**：用 Riverpod 把 `PlannerService` 的数据流暴露给界面，并保存这些临时状态：拖动状态、当前选中的卡片或连线、编辑状态、**撤销栈**。拖动过程中的卡片位置**只存在内存里**，松手时才写入数据库。
3. **业务层：`PlannerService`**：所有业务规则都在这里，例如连线切换、完成、回收站、顺延、历史记录、清理。它是纯 Dart 代码，不依赖 Flutter 界面，通过构造参数注入**数据存储**、**时钟**和 **ID 生成器**。它是**测试切入点 1**。
4. **数据层**：用 drift（SQLite）做本地存储，三个平台都能用。测试时换成内存版 SQLite。

选择理由：只做本地存储加一个业务门面类，就足以支撑 MVP 和以后的同步，不需要引入 Bloc、Clean Architecture 那种多层用例类。

v2 的改动没有改变分层：历史记录是数据层多一张表、业务层多一些规则；点击断开和撤销只是在业务层多了 `removeLink` / `restoreLink` 两个操作；快捷键和撤销栈属于界面状态层。

**CarryOverRecord（顺延历史记录）**：v2 新增

| 字段 | 类型 | 规则 |
|---|---|---|
| id | UUID | 主键 |
| cardId | UUID | 被顺延的卡片 |
| fromDayKey | 文本 | 顺延前所在的日期，也就是这条记录显示在哪一天 |
| toDayKey | 文本 | 这次顺延到了哪一天 |
| x, y, width, height | 小数 | 顺延前在原画布上的位置和大小 |
| titleSnapshot | 文本 | 顺延时的标题 |
| colorArgb | 整数 | 顺延时的颜色 |
| carriedAt | 时间 | 顺延发生的时间 |
| createdAt, updatedAt | 时间 | |

规则：
- **只有 `TaskCard` 是有效任务。** 历史记录只是"快照 + 指向卡片的指针"，它不计入任何数量统计，也没有完成、删除、连线这些操作。所以全局任何时候，一个任务只有一张有效卡片。
- 同一张卡片顺延多次（例如 10-18 → 10-19 → 10-20）时，每次顺延都在出发的那一天留一条记录。
- 点击历史记录时，跳转到这张卡片**当前的** `dayKey`，而不是记录里的 `toDayKey`。如果卡片当前在回收站里，提示"该任务在回收站中"；如果已完成，跳到它当前日期并打开"已完成"列表。
- 卡片被**永久删除**时，它的所有历史记录也一起物理删除。
- 历史记录不会被同步删除或修改，所以不需要软删除字段；以后做同步时它是只追加的数据。

**连线什么时候显示**：两端卡片都没删除、都是 `active` 状态、并且在同一天。这个规则让"完成后隐藏 / 恢复后重新显示"不需要专门处理，因为连线记录本身一直都在。历史记录之间不画线。

**AppMeta（键值表）**：`lastMaintenanceDay`（上次执行每日维护的日期）、`schemaVersion`（数据库结构版本）。

### 顺延排布算法（v2 修改）

1. 找出所有 `dayKey < 今天`、`status = active`、没有删除的卡片，按当前日期分组。
2. **为每张卡片写一条 `CarryOverRecord`**：`fromDayKey` 是它当前的日期，`toDayKey` 是今天，位置、大小、标题、颜色取顺延前的值。
3. 每组保持组内卡片的相对位置（每组按自己的外接矩形对齐到原点）。多个组**从上到下堆叠**，最早的日期在最上面，组之间间隔 48。整体放到今天画布的左上角，留 24 的边距。
4. 今天已有的卡片全部向右移动"顺延区宽度 + 48"。
5. 把被顺延卡片的 `dayKey` 改成今天，`carriedOver` 设为 true。组内卡片之间的连线会自动跟着显示（因为两端现在同一天）；和留在旧日期的卡片之间的连线不再显示（跨天了），但记录保留。
6. 未来日期的卡片不受影响。步骤 1–5 在**一个事务**里完成，所以不会出现"卡片已经搬走但没留下历史记录"或者"历史记录有了但卡片还在原处"的中间状态。

单张卡片立即顺延（`uncompleteCard` / `restoreCard` 触发时）用同一套规则，只是这一组只有一张卡片。

#### 系统时钟回拨时的例外（v3.1）

正常时钟下，"今天"就是时钟的今天，上面的规则和 AC-21 不变。系统时钟被调回过去时（时钟的今天早于 `lastMaintenanceDay`），按下面的规则处理：

- **effectiveToday** = max(时钟的今天, `lastMaintenanceDay`)；`lastMaintenanceDay` 不存在时就是时钟的今天。
- 用户取消完成、或者从回收站恢复一张 active 卡片时：卡片日期**早于** effectiveToday → 立即顺延到 effectiveToday（并生成历史记录）；卡片日期**等于或晚于** effectiveToday → 保留原日期和位置。
- 自动的 `runDailyMaintenance` 在时钟回拨时照旧跳过顺延，也不把 `lastMaintenanceDay` 改小（AC-33）。
- 原因：`lastMaintenanceDay` 以前的未完成卡片在上次维护时都已经顺延走了。如果按回拨后的时钟顺延，卡片会被搬到比 `lastMaintenanceDay` 还早的日子；时钟恢复到 `lastMaintenanceDay` 那天时，同一天不再维护，这张未完成卡片就一直留在过去的日子里，不出现在今天的画布上。以 effectiveToday 为准，卡片放在最近一次维护的日期上，时钟恢复后按正常规则继续顺延，任何时候都只有一张有效卡片（AC-28）。
- 这是 AC-21 在系统时钟异常时的明确例外：日期在时钟的今天和 `lastMaintenanceDay` 之间的卡片，取消完成或恢复后会出现在 `lastMaintenanceDay` 那天，而不是留在原日期。

### 拖动交互状态机

| 状态 | 进入条件 | 在这个状态里 | 松手时 |
|---|---|---|---|
| `idle` | 初始 | | |
| `dragging` | 手指按在卡片上开始移动（桌面上是鼠标左键按下拖动） | 卡片跟着手指走；显示底部投放区 | 落在投放区 → 完成或删除；否则 → `moveCard` 到新位置 |
| `hovering(target)` | **指针位置**进入另一张卡片的范围 | 开始计时；离开这张卡片 → 回到 `dragging` | 当作普通移动处理 |
| `armed(target, action)` | 在 `hovering` 里持续 400ms | 目标卡片放大到 1.05 倍并发光；action 为"连线"时显示虚线预览，为"断开"时显示 ✂️ | 被拖卡片立即动画弹回起点，同时异步执行 `toggleLink`；保存成功后 Android 手机振动（见下方"松手后的时序"） |

- 判断碰撞看的是**指针所在位置**，不是两张卡片的矩形是否重叠，这样结果更可预测。
- 碰撞范围是卡片在画布上原本的矩形（画布坐标，跟着平移和缩放），不包括 armed 时目标卡片放大 1.05 倍多出来的那一圈。放大只是视觉效果，不会改变碰撞范围，所以不会因为放大反复进入、退出 armed。
- **松手后的时序**（#18 已确认的实现决策）：在 armed 状态松手，被拖卡片**立即**开始弹回动画，`toggleLink` 异步保存，不等保存完成。保存成功后 Android 手机轻微振动；保存失败时不振动，连线保持原状，卡片照样回到起点，并提示"保存失败，请重试"。
- 已知限制（#20 确认保留）：同一时间只播放一个弹回动画。弹回还没播完时又有一张卡片要弹回（再次连线，或者拖进投放区保存失败），前一张直接跳到起点。这只是视觉上的中断，卡片位置、连线和存储都不受影响。
- 投放区的优先级高于卡片碰撞。
- **投放区的细节**（#20 已确认的实现决策）：
  - 按**指针位置**判断进没进投放区，不看卡片矩形和投放区重叠多少。投放区固定在屏幕底部（避开 Android 的手势导航条），不跟着画布平移和缩放，所以按屏幕坐标判断；卡片之间的碰撞仍然按画布坐标判断。
  - 指针进入投放区时取消 `hovering` / `armed` 和连线预览，松手是投放；离开投放区回到普通拖动，再停到卡片上重新计时。
  - 投放区只在拖动卡片时显示，指针所在的那个高亮；拖动时右下角的"＋"隐藏。投放区不接收点击和手势，不影响画布的平移和缩放。
  - 松手后乐观更新：拖进 ✅ 区的卡片在松手的位置打勾消失（约 200ms），拖进 🗑️ 区的立即消失，`completeCard` / `deleteCard` 异步保存。保存失败时卡片从松手的位置弹回起点，提示"保存失败，请重试"，不显示撤销提示。
- 历史记录**不参与**碰撞：拖着卡片停在历史记录上不会触发任何东西。
- 手势冲突的处理：在卡片上拖动由卡片自己处理，不会传给画布去平移；在空白处拖动才是平移。按住卡片约 500ms、移动没有超过 Flutter 长按手势允许的阈值时弹出菜单；超过阈值进入拖动时不弹菜单。长按菜单和拖动互斥：弹出菜单后不再拖动，开始拖动后不再弹菜单。

### 点击和选中规则（v2 修改，解决 v1 的冲突）

v1 里"点一下卡片就编辑"（故事 18）和"选中卡片后拖手柄调大小"（故事 22）互相矛盾，因为没有定义怎么"选中"。v2 统一成下面的规则，手机和 Windows 都一样：

| 操作对象 | 单击 | 双击 | 长按 / 右键 |
|---|---|---|---|
| 未选中的卡片 | 选中（显示调整大小的手柄） | 完成 | 菜单：改颜色、编辑、删除 |
| 已选中的卡片 | 进入编辑 | 完成 | 同上 |
| 连线（判定范围内） | 选中连线：高亮，并在中点显示 ✂️ | 和单击一样 | 仅右键（手机上没有）：菜单"断开连线" |
| 连线中点的 ✂️ | `removeLink`，线淡出 | | |
| 历史记录 | 跳转到卡片当前所在的日期，并选中它 | 和单击一样 | 无 |
| 空白处 | 取消所有选中 | 新建卡片（过去的日期上不起作用） | 无 |

- 同一时间最多选中一个对象（一张卡片或一条连线）。
- **过去的日期**（v3）：不显示"＋"按钮；双击空白处和 Ctrl+N 都不起作用，不弹提示。其他操作照常可用，例如查看历史记录、打开"已完成"列表。
- 因为要区分单击和双击，单击会在双击判定时间（Flutter 默认约 300ms）之后才生效。
- **命中优先级**（从高到低）：✂️ 按钮 > 卡片 > 历史记录 > 连线 > 空白处。卡片盖在连线上面时，点击算点卡片。
- **连线判定范围**：在当前缩放比例下，点到贝塞尔曲线的距离 ≤ 12 逻辑像素。
- **点击连线的细节**（#19 已确认的实现决策）：
  - 判定范围内有几条连线时选最近的一条；一样近（曲线重叠）时选画在上面的那条。
  - ✂️ 盖在画布上面，跟着连线中点、画布的平移和缩放移动，大小不随缩放变化：图标 32 逻辑像素，点击范围 44 × 44。点 ✂️ 立即生效，不等双击判定。
  - 删除成功后连线才淡出；失败时提示"保存失败，请重试"，连线和选中都不变。
  - 右键连线和右键卡片一样，不区分平台（手机上没有右键）；右键不改变选中。
  - 双击的第一下点在连线上、第二下偏出了判定范围时，也算双击连线，不新建卡片。
  - 拖动卡片时选中的连线保持选中；选中的连线不再显示（断开，或一端完成、删除）时自动取消选中。
  - 从连线上开始拖动是平移画布。正在编辑卡片时点连线，先保存编辑；保存失败时停在编辑状态，不选中连线。
- **双击完成的细节**（#20 已确认的实现决策）：
  - 双击完成和拖进 ✅ 区走同一套逻辑：打勾消失（约 200ms），保存失败时卡片回到原处，提示"保存失败，请重试"。
  - 正在编辑的卡片和还没保存的新卡片不能双击完成；在编辑框里双击照常选文字。
  - 双击的第一下点在卡片（包括选中卡片右下角的手柄）上、第二下偏出卡片落在空白处时，也算双击这张卡片（完成），不新建卡片（#50）。第一下点在正在编辑的卡片、或者还没保存的新卡片上时什么都不做：不新建卡片，新卡片里输入的内容不丢。

### 断开连线的两种方式（v2）

| 方式 | 触发规则 | 确认步骤 | 适用平台 |
|---|---|---|---|
| **A. 再次碰撞** | 把两张已连接卡片中的任一张拖到另一张上，停留 400ms 出现 ✂️ 预览，松手 | 预览 + 松手 | 全部 |
| **B. 点击连线** | 单击连线 → 高亮并显示 ✂️ → 再单击 ✂️ | 两步点击 | 全部 |
| **B'. 右键连线** | 右键点连线 → 菜单"断开连线" | 菜单选择 | 有鼠标右键的平台（Windows） |

三种方式都会让线淡出（200ms），都可以用 Ctrl+Z 撤销（Windows）。A 走 `toggleLink`，B 和 B' 走 `removeLink`。

### 卡片内容显示（v2 修改，v3 补充）

- 从上到下：标题（自动换行，超出卡片高度时省略）→ **备注第一行**（单行，超出部分用省略号；比标题小一号，颜色淡一些；没有备注时不显示这一行，也不留空白）→ 右上角的"顺延"标记（如果有；单独占右边一列，标题和备注排在它左边，见"历史记录的细节"）。
- **"顺延"标记**（v3）：画布上的卡片只要 `carriedOver = true` 就显示。完成后卡片离开画布，标记也就看不到了；取消完成后卡片回到画布，标记会再次出现。"已完成"列表和回收站里不显示这个标记。
- "备注第一行"指的是备注文本中第一个换行符之前的内容。如果第一行是空的，就取第一个非空行。

### 历史记录显示（v2 新增）

- 画在原日期画布上顺延前的位置和大小，使用当时的颜色，**不透明度 40%**，边框是虚线。
- 内容：标题快照（单行省略），下面一行是"→ 已顺延至 Oct 20"（日期用下面"日期格式"里的短格式）。
- 永远画在有效卡片下面。
- **历史记录的细节**（#21 已确认的实现决策）：
  - 从下到上依次是：连线 → 连线的点击区域 → 历史记录 → 有效卡片。历史记录画在连线上面，所以点在历史记录上的连线算点历史记录；✂️ 仍然在最上面。
  - 单击和双击都会跳转。和点卡片一样，单击要等双击判定（约 300ms）后才生效。长按、右键什么都不做。从历史记录上开始拖动是平移画布。双击的第一下点在历史记录上、第二下偏出去时，也算双击历史记录，不新建卡片。
  - 先用 `findCard` 查卡片现在在哪（存储里的真实状态），再保存正在编辑的卡片并退出编辑，然后马上按查到的结果处理。保存失败时停在编辑状态，不跳转，提示"保存失败，请重试"（查卡片也失败时同样按保存失败提示）。查到的结果：
    - 在画布上：跳到它所在的日期并选中它。
    - 已完成：跳到它所在的日期，并打开那一天的"已完成"列表（#23）。
    - 在回收站：提示"该任务在回收站中"，不跳转。
    - 找不到：提示"该任务已不存在"，不跳转。
    - 读取失败：提示"读取失败，请重试"，不跳转。
  - 换一天时平移和缩放保持不变，选中和编辑都取消。跳过去的卡片已经完整地在可视区域里时，画布不动；不在里面时，只平移到刚好能完整看到它（离边缘 24 逻辑像素），不改缩放比例。
  - "顺延"标记放在卡片右上角，单独占一列，不盖住标题、备注、编辑框和手柄；编辑时也显示。
  - **切换日期只有一个入口**：选择与撤销控制器的 `showDay`（点历史记录跳转也走它）。切换前先按退出编辑的规则处理正在编辑的内容（标题为空的新卡片丢弃，已有卡片保留原来的内容），保存成功才切换并取消选中；保存失败时停在原来的日期和编辑状态。多次切换按先后顺序一个一个完成，不会互相覆盖。日期抽屉也必须走这个入口。

### 日期格式（v2 新增，v3 改为英文月份缩写）

日期用**英文月份缩写 + 不补零的日期数字**，星期也用英文缩写；界面上的其他文字仍然是中文。只有两种格式，都由"日期格式化"模块输出，固定用 `en_US` 区域设置，不跟随系统语言：

| 名称 | 样式 | 例子 |
|---|---|---|
| **完整格式** | `EEE, MMM d, yyyy` | `Tue, Oct 20, 2026`、`Sun, Nov 1, 2026` |
| **短格式** | `MMM d`；**如果不是今年，后面加 `, yyyy`** | `Oct 20`；`Jan 3, 2027` |

| 位置 | 显示 |
|---|---|
| 顶部标题 | 完整格式 `Tue, Oct 20, 2026`；今天在后面加" · 今天" |
| 日期抽屉的每一行 | `Tue` 和 `Oct 20`（这里**一律不显示年份**，年份放在每一周的日期范围里；当前显示的那一天高亮，今天另有标记） |
| 历史记录 | `已顺延至 Oct 20`（短格式） |
| 已完成列表 | 页面标题用完整格式；每项显示完成时间 `14:30`（24 小时制） |
| 回收站 | 每项显示原日期（完整格式），以及"还剩 N 天" |
| 撤销提示等其他地方 | 短格式 |

- 月份缩写固定是 `Jan Feb Mar Apr May Jun Jul Aug Sep Oct Nov Dec`，星期固定是 `Mon Tue Wed Thu Fri Sat Sun`。
- 日期按设备本地时区计算。数据库里的 `dayKey` 仍然存 `YYYY-MM-DD`，只有显示时才格式化。

|---|---|---|
| `Delete` / `Backspace` | 选中的卡片移到回收站（同样会显示撤销提示） | 选中了卡片，并且不在编辑状态 |
| `Ctrl+Z` | 撤销（见下方"撤销栈"） | 不在编辑状态；编辑状态下交给文本框撤销输入的文字 |

| `Ctrl+N` | 在可视区域中间新建卡片，并进入标题编辑 | 当前日期不是过去 |

### 撤销栈（v2 新增）

- 只记录 4 类操作：**移动卡片、完成、删除、连线/断开（包括三种断开方式）**。其他操作（新建、改文字、改颜色、改大小、取消完成、从回收站恢复）不进撤销栈。
- 每类操作对应的撤销动作：
  - 移动 → `moveCard` 回到原来的位置
  - 完成 → `uncompleteCard`
  - 删除 → `restoreCard`
  - 新建连线 → `removeLink`
  - 断开连线 → `restoreLink`
  - 碰撞后的"弹回原位"不算移动，不进撤销栈。
- 撤销栈只存在内存里，最多 50 条。下列情况会**清空**：切换日期、App 重启、执行了顺延的每日维护。这样撤销永远只作用于当前看到的这一天。
- 撤销失败时（例如 `restoreLink` 返回 `InvalidState`），丢弃这一条，并显示提示"无法撤销"。
- 按钮形式的删除撤销提示（故事 51，手机和 Windows 都有）继续保留，它直接调用 `restoreCard`，和撤销栈互不影响；撤销提示点过之后，撤销栈里对应的那条在执行时会因为卡片已经恢复而变成空操作。
- **删除撤销提示的细节**（#20 已确认的实现决策）：
  - 菜单里删除、拖进 🗑️ 区（以后还有 `Delete` 键，#26）共用一个提示：删除保存成功后才显示"已移到回收站：『卡片标题』"和"撤销"按钮，约 4 秒后自己消失。
  - 新的提示顶替旧的；每个提示只恢复它自己那张卡片。
  - 恢复时遵守顺延规则：卡片原来的日期已经过去、被顺延到 effectiveToday 时，另外提示"已恢复至今天（Oct 20）"（短格式）。恢复失败时提示"恢复失败，请重试"。
  - 撤销提示（以及其他提示，比如"保存失败，请重试"）和右下角的"＋"不互相遮挡：提示出现时"＋"按 Material 的布局让到提示上面，提示消失后回到右下角；不靠隐藏"＋"来避开。

### 连线绘制

- 三次贝塞尔曲线。起点和终点取两张卡片中**距离最近的那一对边的中点**，控制点沿着边的法线方向，偏移量取两点距离的 40%（但不超过 120）。
- 箭头画在终点，线宽 2，颜色是半透明的深灰；**选中时**线宽 3，颜色变成强调色。
- 新建连线时有 300ms 的"画出来"动画，断开时 200ms 淡出。

### 颜色

- 预设 8 种颜色：淡黄（默认）、淡橙、淡粉、淡紫、淡蓝、淡绿、淡灰、白。淡黄是 `#FFF0B8`，淡蓝是 `#DBEBFF`（v4，取自参考图）；其余预设可以按参考图的柔和程度微调。
- 改预设色值不改已经保存的卡片：v4 以前的卡片仍然是原来的色值，色板里不显示成"选中"，可以重新选一次（v4）。
- 深色主题下卡片颜色不变（便签仍然是浅色），文字颜色仍然按卡片背景决定（v4）。
- "自定义"使用 `flex_color_picker`。
- 文字颜色：背景的相对亮度大于 0.5 时用近黑色，否则用白色。

### 自适应布局（v4 新增）

参考图：`docs/ui/references/shared/responsive_planner_original.png`（完整）、`docs/ui/references/android/compact_canvas_reference.png`（窄屏）、`docs/ui/references/windows/expanded_sidebar_reference.png`（宽屏）。说明见 `docs/ui/design-references.md`。目录名 `android` / `windows` 只是分类，不代表按平台分界面。

- **一套界面**：Windows 和 Android 用同一个画布页面、页头、日期列表、画布和卡片组件。不写 `AndroidScreen` / `WindowsScreen` 这类分开的页面；布局只看 `LayoutBuilder` 给出的整个页面的宽度（不是减去侧栏以后的画布宽度，不然侧栏一展开就可能跨回窄屏，布局来回跳），不看 `Platform` / `defaultTargetPlatform`。平台判断只留给输入方式的增强（快捷键、右键、振动）。
- **断点**：页面宽度 ≥ 840 逻辑像素是宽屏，否则是窄屏。840 是一个常量，可以按实际体验调整。
- **窄屏**：和 v3 的日期抽屉一样（AC-2）。
- **宽屏**：日期侧栏常驻在画布左边，默认展开；页头左边的按钮折叠、展开侧栏。折叠以后画布占满宽度。宽屏时没有抽屉，也不认从左边缘拉出的手势。折叠状态只在这次运行内记住，不写入存储。
- **跨过断点**（拖动窗口、旋转、分屏）：显示的日期、选中、正在编辑的内容和输入焦点、正在进行的拖动都不丢；窄屏时抽屉开着、变成宽屏后抽屉带动画关上，换成侧栏；宽屏变窄屏时侧栏收起，抽屉默认关着。
- **画布的平移**：用户点按钮展开或折叠侧栏时，画布反向平移侧栏宽度的变化量，让卡片在屏幕上的位置不动。因为跨过断点而出现或消失的侧栏不算，和窗口变大变小一样处理。窗口本身变大变小时平移和缩放不变（以可视区域左上角为准），可能有卡片暂时跑到可视区域外面，可以平移回来。
- **不写数据**：窗口大小、断点、侧栏的变化都只改视图，不改任何卡片的坐标和大小，不写数据库。
- Windows 的标题栏用系统原生的；参考图里仿出来的标题栏只是示意。

### 错误处理

- **数据库打不开**：显示全屏错误页，带"重试"按钮和错误信息，不进入画布，防止在空数据上继续操作把数据覆盖掉。
- **写入失败**：界面状态回到写入前，底部提示"保存失败，请重试"。
- **非法操作**（例如对已删除的卡片连线）：界面层在调用前先防一次；万一 `InvalidState` 真的发生，静默忽略并记录日志（撤销例外，见"撤销栈"）。
- **点击历史记录时卡片找不到**（理论上不会发生，因为永久删除时历史记录也一起删了）：提示"该任务已不存在"。
- **数据库结构升级**：用 drift 的版本迁移。每次改表结构都要写迁移和对应的迁移测试。

### 认证与安全

- MVP **不需要登录**，只有一个本地用户。
- 数据存在系统分配给 App 的私有目录里。MVP 不需要网络权限，也没有统计、埋点或崩溃上报。
- 仓库是公开的：Android 签名的 keystore 和 `key.properties` 已经在 `.gitignore` 里，必须放在仓库外面保管；以后的 Supabase 密钥也不能提交。
- 以后接入同步时：用 Supabase Auth（邮箱 magic link）登录，所有表开启 RLS（行级安全），按 `user_id` 隔离数据。

## Testing Decisions

### 什么是好的测试

- 只测**对外的行为**：调用公开的操作，然后检查读回来的状态或屏幕上看到的内容；不检查内部的私有方法、不检查 SQL、不用 mock 去验证调用次数。
- 尽量用真实的依赖：真实的 `PlannerService` 加内存版 SQLite；**时钟**是假的（用 `clock` 包注入），这样"第二天""10 天后"可以直接模拟。
- 唯一的例外（v3）：测试存储失败（AC-40、AC-41，以及 #21 点历史记录时读取失败）时，给 `PlannerService` 注入一个**会报错的存储**。存储本来就是通过构造参数注入的，所以不需要新增切入点。它只用来模拟失败，不用来验证调用次数。
- 一个测试只讲一个行为，测试名用中文描述这个行为，例如"再次碰撞已连接的两张卡片会断开连线"。
- 上面每条没有标 🖐 的验收标准都至少对应一个测试。

### 切入点 1：PlannerService（主要）

覆盖所有业务规则，至少包括：
- 新建：空标题被拒绝；颜色默认是淡黄；尺寸被截断到上下限以内；在过去的日期新建被拒绝（AC-43）。
- 卡片属性：改颜色、改大小、改内容后重新打开数据库仍然保持（AC-11、AC-44）；`carriedOver` 在完成、取消完成、删除、恢复之后都保持 true（AC-47）。
- 连线：第一次碰撞新建 dragged → target；再碰一次（不管哪个方向）就断开；`removeLink` 断开并且幂等；`restoreLink` 能恢复，但在冲突时被拒绝；可以有多条线；同一张卡片、跨天、已完成或已删除的卡片会被拒绝；可见连线的规则正确。
- 完成：卡片从画布消失，出现在"已完成"列表并带完成时间；取消完成后回到原位，连线重新显示；在过去的日期取消完成会触发顺延。
- 回收站：删除后从画布消失；恢复后连线也回来；剩余天数计算正确；第 10 天还在，超过 10 天被清理，相关连线和历史记录也被物理删除；永久删除和清空回收站正常。
- 顺延：单天顺延的位置和相对布局正确；今天已有的卡片右移，没有重叠；多天顺延时按日期从上到下堆叠；**每次顺延都生成正确的历史记录**（日期、位置、标题、颜色快照）；**有效卡片不重复**；历史记录不计入未完成数；同一天执行两次结果不变（幂等）；未来日期不受影响；时钟回拨时跳过顺延；恢复一张过去日期的卡片会触发顺延；时钟回拨时取消完成和恢复以 effectiveToday 为准（卡片日期早于、介于时钟的今天和维护日期之间、等于维护日期，以及时钟恢复后的状态）；`findCard` 返回卡片当前的位置。
- 存储：重新打开数据库后数据完整（同一个内存数据库实例，重建 service）；每次结构升级都有迁移测试；注入会报错的存储时，写操作抛出 `StorageFailure`，数据不变（AC-40）；`findCard` 读取失败时也抛出 `StorageFailure`。
- 纯函数（属于"Planner 核心模型"和"日期格式化"，通过直接调用测试）：日期的完整格式和短格式，包括不补零、跨年加年份、系统语言为中文时仍输出英文（AC-4）；文字颜色按背景亮度切换黑白（AC-10）。

## Out of Scope

以下内容**不在本 spec 范围内**：
- 多设备同步、Supabase、登录。
- 连线的依赖关系（锁定后续任务）和时间轴（时间、预计时长）。
- 子任务清单、提醒和通知、重复任务。
- 字体选择。（深色模式 v4 起纳入范围）
- iOS 版本（第二阶段）。
- 数据导入导出和备份（见风险部分）。
- 统计报表（数据已经保留了，界面以后再做）。
- 多人协作、分享。
- 平板和横屏的专门适配：v4 起统一按页面宽度自适应（见"自适应布局"），不再为平板、横屏另做界面。
- 记住每天画布的平移和缩放位置。
- Android 外接键盘的快捷键；用快捷键操作连线；Ctrl+Y / Ctrl+Shift+Z 重做。
- 撤销"新建、改文字、改颜色、改大小、取消完成、从回收站恢复"这些操作。

## Further Notes

### 已确认的决策（原"假设"，现在都已由用户确认）

1. 连续几天没打开 App 时，之前**所有**没完成的任务都顺延到今天，按日期从上到下堆叠。
2. 顺延时**有效卡片搬到今天**，原日期留下只读的历史记录；全局只有一张有效卡片。
3. 已完成的卡片在当天的"已完成"列表里查看，可以在那里取消完成或删除。
4. 新建卡片：双击空白处、点"＋"按钮，或 Windows 上按 Ctrl+N。
5. 断开连线有两种方式：再次碰撞，或者点击连线再点 ✂️（Windows 上还可以右键）。
6. 删除卡片时保留它的连线记录，这样恢复时连线也能回来；只有永久删除时才删掉连线。
7. 卡片被顺延过以后，`carriedOver` 永远是 true；画布上的卡片只要被顺延过就显示"顺延"标记，"已完成"列表和回收站里不显示。（v3 统一了 v2 中两处不一致的说法）
8. 每天大约有 50 张以内的卡片，不需要做虚拟化之类的性能优化。
9. 卡片上只显示备注的第一行。
10. 日期用英文月份缩写：完整格式 `Tue, Oct 20, 2026`，短格式 `Oct 20`（不是今年时加年份），日期抽屉一律是 `Oct 20` / `Tue`。（v3，替换 v2 的 `YYYY-MM-DD 周X`）
11. Windows 快捷键和撤销栈按上面的表格实现。
12. 过去的日期只能查看，不能新建卡片（v3）。
13. 长按卡片（Windows 上右键）弹出菜单（改颜色、编辑、删除），改颜色时再打开色板；DESIGN.md 里原来写的"长按打开色板"已同步更新（v3）。
14. 日期抽屉里的数字显示当天的**未完成数**（v3）。
15. Windows 和 Android 用同一套界面，按页面宽度在日期抽屉和常驻侧栏之间切换，断点先用 840（v4）。
16. 视觉以 `docs/ui/` 的参考图为准；新卡片默认色改成 `#FFF0B8`，已保存的卡片颜色不变（v4）。
17. 宽屏也用悬浮的"＋"新建卡片，不在页头另放一个（v4）。
18. 折叠、展开侧栏时画布反向平移，卡片在屏幕上不动；窗口大小变化只改视图，不写数据（v4）。

### 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| `InteractiveViewer` 的平移缩放和卡片拖动、长按、单击、双击、点击连线这些手势互相冲突 | 核心交互可能不顺手 | **先做原型**，在 Android 真机和 Windows 上都验证手势，再写正式代码 |
| 为了区分单击和双击，单击要等约 300ms 才生效 | 选中卡片会感觉有点慢 | 原型阶段实际体验；如果太慢，可以把"完成"的双击改成别的手势 |
| 画布缩放后的坐标换算出错 | 碰撞判断、投放位置、点击连线的位置偏移 | 所有命中判断都在画布坐标系里做，并为缩放后的情况写 widget 测试 |
| 只存在本机，没有备份 | 手机丢失或重装后数据没了 | MVP 接受这个风险；第二版的同步可以解决 |
| Windows 和 Android 的开发环境还没装 | 无法开始开发 | 第一个任务就是装环境，并跑通示例项目 |
| 时区或系统时钟变化 | 顺延发生在错误的日期 | 日期统一按本地时区计算；时钟回拨时跳过顺延；写测试覆盖 |
| iOS 免费签名每 7 天过期 | 第二阶段使用不便 | 到时在 AltStore 和 99 美元/年的开发者账号之间选 |
