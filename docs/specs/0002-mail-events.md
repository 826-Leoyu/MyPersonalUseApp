## Problem Statement

目标用户是一名学生，电脑操作不熟练。她的学校 Outlook 邮箱每天会收到很多邮件，包括作业截止、表格提交、讲座活动、系里通知、广告推广等等，重要的事情混在一大堆邮件里，很容易漏掉。她要的不是一个新的邮件客户端，而是**有人帮她把邮件里"要做的事"挑出来**，放进她已经在用的每日任务画布里。

限制条件：

- 学校账号进不了 Microsoft Entra 的应用注册页面，所以不能自己注册应用来直连 Graph。
- 软件装在她的电脑上，开发者的电脑、账号、路径、测试邮箱、Power Automate 连接和任何凭据都不能带进去。
- 她不会去折腾 API 密钥、命令行或配置文件。
- 邮件内容不可信（可能有钓鱼或者故意写给 AI 的指令），也不能动她 Outlook 里的任何东西。

## Solution

邮件按下面这条路走，每一段都在她自己的账号和电脑上：

```
她的 Outlook 收件箱
 → 她账号下的 Power Automate 流程（每天 07:00 和 16:00）
 → 她的 OneDrive 文件夹里的导出文件
 → OneDrive 同步到她的 Windows 电脑
 → DailyNote 导入、去重
 → 她电脑上已登录的 Claude Code（她自己的会员）分析
 → 画布旁边的"新邮件事项"栏
 → 她点 [加入] 后变成一张普通卡片
```

她看到的是：

- 打开 DailyNote，还是熟悉的当天画布。画布旁边多了一个**"新邮件事项 (3)"**栏，每条有 **[加入]** 和 **[忽略]**。
- 垃圾邮件、广告和仅供参考的通知不会出现在栏里，但可以在"已过滤的邮件"里找回来。
- 点 [加入] 后，事项变成今天画布上的一张卡片（可以改放到以后的某一天），卡片标题下面多一行时间，例如 `⏰ 截止 Oct 30 23:59`。之后和其他卡片一样：拖动、双击完成，没做完的第二天自动顺延。
- 老师之后发邮件说"作业延期了"，不会重复建卡，而是在原卡片上提示"有更新"，她点 [采用] 才会改。
- 栏的顶部一直显示导入状态，出问题时说清楚是哪一步出了问题。

DailyNote 不需要她的邮箱密码，不保存任何 AI 密钥，自己也不联网：取邮件靠 Power Automate 和 OneDrive，分析靠她电脑上登录的官方 Claude Code。

## User Stories

### 首次设置

1. 作为目标用户，我希望第一次打开邮件功能时有一个分步骤的设置向导，这样我不用自己摸索该先做什么。
2. 作为目标用户，我希望向导一开始就告诉我"邮件内容会交给你自己账号下的 Claude 分析，不会改动、删除或回复 Outlook 里的邮件"，并且要我勾选同意后才继续，这样我知道自己的邮件被怎么使用。
3. 作为目标用户，我希望用 Windows 自带的文件夹选择窗口选邮件文件夹，而不是手动输入路径。
4. 作为目标用户，我希望选完文件夹后马上看到检查结果（找到几个文件、最新一个是什么时候生成的），这样我知道选对了没有。
5. 作为目标用户，我希望向导帮我检查 Claude Code 是否已经安装、是否已经登录；没安装时提示我请设置者检查，没登录时告诉我怎么登录，这样分析功能第一次就能用。
6. 作为目标用户，我希望登录 Claude 时是我自己在官方的登录页面里完成，这样我的账号密码不会经过 DailyNote 或任何别人。
7. 作为目标用户，我希望向导最后用一封内置的示例邮件试分析一次，这样设置完我就知道整条路是通的。
8. 作为目标用户，我希望在设置页里随时重新打开向导、重新选择文件夹，这样换了电脑或者 OneDrive 文件夹位置变了也能继续用。
9. 作为目标用户，我希望在设置页里填一次我的邮箱地址，这样旧格式的导出文件也能正确去重。
10. 作为目标用户，我希望所有设置只保存在这台电脑上，不跟着安装包走。
11. 作为设置者（帮她安装的人），我希望有一份图文说明，告诉我在她的 Power Automate 账号里一步一步怎么建导出流程，每个表达式原样照填。
12. 作为设置者，我希望另外有一个干净的流程包可以导入，导入时要求重新选择她自己的 Outlook 和 OneDrive 连接，这样不会带上我的连接。
13. 作为设置者，我希望说明的最后有一个验收步骤（手动运行一次，确认 OneDrive 里出现新文件，并检查几个还没验证过的连接器行为），这样我能确认她的账号确实支持。

### 导入

14. 作为目标用户，我希望打开 DailyNote 时它自动检查有没有新的导出文件，这样我什么都不用点。
15. 作为目标用户，我希望 DailyNote 开着的时候每隔几分钟自己检查一次，这样下午的邮件当天就能看到。
16. 作为目标用户，我希望有一个 [立即导入] 按钮，这样我想马上看的时候不用等。
17. 作为开发者，我希望在第一阶段能手动选择一个 JSON 文件导入，这样不依赖 Power Automate 就能把导入和去重做对。
18. 作为目标用户，我希望 DailyNote 不会读到写了一半或者还没同步完的文件，这样不会出现乱码或者漏邮件。
19. 作为目标用户，我希望同一封邮件出现在多个导出文件里时只算一封，这样不会重复出现事项。
20. 作为目标用户，我希望同一个文件被导入两次（比如 OneDrive 生成了副本）时什么都不会重复，也不会重复花我的 Claude 额度。
21. 作为目标用户，我希望 DailyNote 导入到一半被关掉，下次打开能接着做完，而不是漏掉或者重复。
22. 作为目标用户，我希望 DailyNote 发现两个导出文件之间可能漏了邮件时提醒我，这样我可以让设置者手动补读。
23. 作为目标用户，我希望 DailyNote 自动清理已经处理完、超过 14 天的导出文件，这样 OneDrive 不会越堆越多。
24. 作为目标用户，我希望 DailyNote 绝不改动、移动、删除或回复 Outlook 里的邮件。

### 导入状态

25. 作为目标用户，我希望在栏的顶部一直看到"上次导入：今天 07:12 · 新邮件 5 封"，这样我知道它在正常工作。
26. 作为目标用户，我希望文件夹找不到时看到"找不到邮件文件夹"和 [重新选择] 按钮。
27. 作为目标用户，我希望文件还在同步时看到"有文件正在同步，稍后自动导入"，而不是报错。
28. 作为目标用户，我希望文件格式不对时看到具体是哪个文件，并且这个文件被跳过，不影响其他文件。
29. 作为目标用户，我希望超过 2 天没有新文件时被提醒去检查 Power Automate 流程。
30. 作为目标用户，我希望状态栏写明"这里只能说明电脑上收到了文件，不代表云端流程现在还在正常运行"，这样我不会误以为一切正常。

### 分析

31. 作为目标用户，我希望新邮件导入后自动分析，我不用点任何按钮。
32. 作为目标用户，我希望第一次设置时只分析最近 14 天的邮件，这样不会一下子用掉大量 Claude 额度。
33. 作为目标用户，我希望更早的邮件也能在需要时手动分析。
34. 作为目标用户，我希望每天自动分析的邮件有上限（100 封），超过时暂停并告诉我，由我决定要不要继续。
35. 作为目标用户，我希望每封邮件被分成"需要行动""可选活动""仅供参考""低价值"四类。
36. 作为目标用户，我希望一封邮件可以提取出好几件事，也可以一件都没有。
37. 作为目标用户，我希望每件事有标题、摘要、要做什么、活动时间或截止时间、地点、相关链接，并能看到是从哪封邮件来的。
38. 作为目标用户，我希望"明天""下周四"这种说法按邮件的收件时间和我的时区换算成具体日期。
39. 作为目标用户，我希望时间不明确时标成"待确认"，而不是让 AI 编一个时间。
40. 作为目标用户，我希望邮件签名里的地址不会被当成活动地点，引用的旧邮件内容不会被当成最新要求。
41. 作为目标用户，我希望邮件有附件或图片时提示"附件或图片未分析"，这样我知道可能还需要自己看一下原邮件。
42. 作为目标用户，我希望邮件里写给 AI 的"指令"不会被执行，分析结果只能是固定格式的数据。
43. 作为目标用户，我希望 Claude 分析时不能读写我电脑上的任何文件、不能执行任何命令。
44. 作为目标用户，我希望发给 Claude 的只有分析需要的内容（主题、发件人、时间、正文文本、链接），不包括完整的邮件头、收件人列表和附件。
45. 作为目标用户，我希望分析失败的邮件不会被当成"处理完了"，之后会自动重试。
46. 作为目标用户，我希望 Claude 额度用完时分析自动暂停，等额度恢复后自己继续。
47. 作为目标用户，我希望 Claude Code 没安装或没登录时看到清楚的提示，而不是一直默默失败。
48. 作为目标用户，我希望一封邮件分析失败不影响其他邮件。

### "新邮件事项"栏

## Implementation Decisions

### 架构总览

在 spec 0001 的四层结构上加一个**邮件模块**，和 `PlannerService` 平级，依赖方向不变：

```
界面层：画布、"新邮件事项"栏、已过滤的邮件、设置向导、卡片时间
界面状态层（Riverpod）
业务层：PlannerService（画布）     MailService（邮件，新增）
                    ↖ 加入时在同一个事务里新建卡片 ↙
数据层：同一个 drift 数据库，邮件用独立的表
外部来源（都通过接口注入）：
  ExportSource   导出文件夹（Windows 上是 OneDrive 同步文件夹）
  MailAnalyzer   分析器（第一版是 Claude Code 命令行）
```

- **邮件来源、分析、事件存储三者分开**。`MailService` 只认"导出文件里的邮件"和"分析器返回的结构化结果"，不知道 Power Automate 或 Claude 的存在。以后换成 Graph、经典版 Outlook 客户端或 Claude API，只是新增一个 `ExportSource` 或 `MailAnalyzer` 的实现。
- `MailService` 是**纯 Dart**，通过构造参数注入：数据库、时钟、ID 生成器、`ExportSource`、`MailAnalyzer`。
- [加入] 需要同时更新邮件事项并新建卡片。`MailService` 和 `PlannerService` 共用同一个数据库，[加入] 调用 `PlannerService` 新增的一个"在调用方事务内新建卡片"的操作，两边在一个事务里完成，任何一步失败都整体回滚。`PlannerService` 不依赖邮件模块。
- 只有 Windows 构建会注册邮件模块和它的界面入口；Android 上这些入口都不出现。

### 模块清单

| 模块 | 职责 |
|---|---|
| **导出文件解析** | 纯函数。把一个文件的字节解析成"导出批次"：信封格式或裸数组，邮件列表，解析错误。同时负责 HTML 转文本（保留链接，标记引用的旧邮件和签名）。不碰数据库 |
| **ExportSource** | 接口：列出文件夹里的 `mail-*.json` 及其大小和修改时间、读取文件、删除文件、检查文件夹是否可用。Windows 实现基于 `dart:io` |
| **MailAnalyzer** | 接口：输入一封邮件的分析请求（见"分析请求"），输出结构化结果或有类型的失败。第一版的实现是 `ClaudeCodeAnalyzer` |
| **ClaudeCodeAnalyzer** | 在本机以子进程方式调用官方 `claude` 命令行（非交互模式），禁用全部工具，在空的临时目录里运行，邮件内容通过标准输入传入，要求固定的 JSON 输出；把退出码和输出翻译成有类型的失败。可执行文件查找和进程启动通过一个可注入的进程运行器完成 |
| **分析结果校验** | 纯函数。校验 Claude 输出的 JSON：字段齐全、分类合法、时间可解析、引用的事项编号确实在请求里给过、链接编号存在。不合法就当作"输出格式不对" |

### 导出文件格式

正式格式（"信封格式"）：

```json
{
  "format": "dailynote-mail-export",
  "version": 1,
  "mailbox": "她的邮箱地址",
  "exportedAt": "2026-10-27T11:00:03Z",
  "messages": [ ...获取电子邮件 (V3) 返回的 value... ]
}
```

- 顶层是数组（现在测试用的格式）也接受，邮箱取设置里的邮箱地址；设置里没有邮箱地址时，这个文件停在 `needsMailbox`，提示去设置页填写。
- `format` 不对、`version` 比已知的大、`messages` 不是数组，都算格式错误。
- 单封邮件缺少 `internetMessageId` 和 `id` 两者时跳过这一封，并计入文件的错误数，不影响同一文件的其他邮件。
- 读取邮件时用到的字段：`id`、`internetMessageId`、`conversationId`、`subject`、`from`、`receivedDateTime`、`body`、`isHtml`、`bodyPreview`、`importance`、`hasAttachments`、`attachments`。`bodyPreview` 只在 `body` 为空（或者转换后什么都没有）时作为后备，并标记"正文可能不完整"。
- 其他字段一律忽略，不保存。

### 正文文本的格式

导入时把 `body` 转成下面这种文本存进邮件的正文文本，分析请求里的正文就是它：

```text
周五组会改到 3 点，地点见 会议室预约 [1]。

- 带上周报

[签名]
李明 | 计算机系
[/签名]

[引用]
From: 王芳
周五组会照常吗？
[/引用]
```

- 段落之间空一行，列表项以 `- ` 或 `1. ` 开头。`isHtml` 为 false 的正文按纯文本处理，保留原来的换行。
- **链接**：只有 `http(s)` 链接编号，编号写在链接文字后面，链接按编号顺序存进邮件的链接列表；同一个链接用同一个编号。纯文本正文（包括用作后备的 `bodyPreview`）里的网址也一样，网址遇到空白、中文或全角标点就结束。
- **图片**：写成 `[图片]`，有替代文字时写成 `[图片: 替代文字]`；1×1 的跟踪像素去掉（宽高写在属性或 `style` 里都算，只写了一边时看那一边）。`cid:` 或 `data:` 开头的图片，或者 `attachments` 里有 `isInline` 的图片附件，记为有内嵌图片。
- **引用的旧邮件**用 `[引用]`…`[/引用]` 包起来：Outlook 的回复和转发分隔块（`appendonsend`、`divRplyFwdMsg`、新版 Outlook 的 `mail-editor-reference-message-container`、经典版 Outlook 顶部有边框的发件人信息块）和它后面的所有内容；`blockquote`；Gmail 的 `gmail_quote`；纯文本里 `-----Original Message-----` 一类的行或一行下划线之后的内容。
- **签名**用 `[签名]`…`[/签名]` 包起来：Outlook `id` 以 Signature 开头的元素、Gmail 的 `gmail_signature`、纯文本里 `-- ` 分隔行之后的内容。引用里的签名不另加标记。认不出来的签名当普通正文保留。
- 什么都没包住的引用或签名不写标记。

### 导入规则

- **什么时候扫描**：App 启动时、运行期间每 5 分钟、点 [立即导入] 时。不使用文件系统监听。一次扫描后还有刚看到、要等下一次扫描才读取的文件时，30 秒后再扫一次（只补一次），不用等 5 分钟。第一阶段另有"选择一个 JSON 文件导入"，走同一套解析和入库逻辑。
- **换文件夹**：旧文件夹里还没读取的文件和格式错误的文件不再记着；已导入的文件留着去重和检查空档，但不再按文件名对应新文件夹里的文件，也不会去删新文件夹里的同名文件。
- **文件可以读的条件**（依次检查）：文件名符合 `mail-*.json`；和上次扫描相比，大小和修改时间都没变；能完整读取并解析。第一次看到的文件只记录，下一次扫描才读取。
- 解析失败时：如果文件已经稳定超过 10 分钟，标为 `invalid`；否则当作"还在同步"，下次再试。读取时 OneDrive 按需下载失败也当作"还在同步"。
- **去重**：先按内容哈希跳过处理过的文件；再按"邮箱 + 邮件键"跳过已经有的邮件。已有邮件**不更新**（同一封邮件的内容不会变）。文件名不参与去重。
- **事务**：一个文件里的所有新邮件和文件状态的更新在同一个事务里提交。中途退出时事务没提交，下次启动整份文件重做；提交了就不会再做。
- **空档检查**：如果新文件的最早收件时间晚于之前已导入文件中最晚的收件时间，并且两个文件都是满的（邮件数等于流程的 Top 值 200），状态栏提示"可能有遗漏，请让设置者手动补读"。所有导入过的文件按收件时间排开，每一处空档都检查，所以一次导入好几个文件时中间的空档也算。提示一直留着，直到补读的文件把空档盖住，或者空档后面那个文件导入满 14 天。
- **首次设置的 14 天**：收件时间早于"首次设置时间 − 14 天"的邮件入库时状态为 `deferredOld`，不自动分析。首次设置时间是第一次选择邮件文件夹和第一次导入中较早的那次，之后不变，换文件夹也不变。
- **导出文件清理**：状态为 `imported`、导入时间超过 14 天、并且其中的邮件都不处于 `pending` 时，由 App 删除文件（OneDrive 会同步删除云端的副本）。`invalid` 的文件不删，留给人看；有人把它删掉以后不再提示。

### 正文保留规则

每封邮件有一个"正文到期时间"，到期后清除正文文本和链接，其他字段保留：

1. 分析出明确的截止时间或活动时间（取它提取出的所有事项里最晚的一个；事项对应的卡片被她改过时间的，以卡片上的为准）：到期时间 = 该时间 + 7 天。
2. 没有明确时间：到期时间 = 收件时间 + 30 天。
3. 同一 `conversationId` 有新邮件导入时，该讨论里所有按规则 2 计算的邮件，到期时间顺延到"新邮件收件时间 + 30 天"。
4. 以下情况不清除：由这封邮件加入的卡片还没完成（在画布上，未完成，没进回收站）；这封邮件的分析状态是 `pending`。
5. 清除在扫描时顺带执行。

清除后，事项详情显示"原文已清理，请在 Outlook 中查看"。[这封有用] 对已清除正文的邮件不可用，提示同一句话。

### 分析请求和结果（MailAnalyzer 的契约）

**请求**只包含：

- 邮件：主题、发件人名称和地址、收件时间（带时区偏移）、重要性、清理后的正文文本（引用的旧邮件和签名用明确的标记包起来）、编号的链接列表、是否有附件、是否有内嵌图片、正文是否可能不完整。
- 当前时区名称。
- "可能相关的现有事项"清单：同一 `conversationId` 已经生成的事项，加上最近 30 天由邮件生成、还没完成的事项。只包含事项编号、标题、活动时间、截止时间和状态，不包含其他邮件的正文。状态就是事项的 `candidate` / `accepted` / `ignored`：卡片已完成或已删除的事项仍然发 `accepted`，不另加状态。分析器因此把它判成 `update` 时，按"更新建议的规则"只会新建一条注明相关事项的候选，不会改卡片，所以不值得为此扩充请求格式。
- 是否被用户标记为有用（为 true 时要求按需要行动处理，实在提取不出事项时返回一条以邮件主题为标题的事项）。

不包含：完整邮件头、收件人列表、附件、原始 HTML。

**结果**：

```
category: actionRequired | optionalEvent | informational | lowValue
reason: 一句话理由（给"已过滤的邮件"用）
items: [
  {
    match: new | update(现有事项编号)
    title, summary, actions[], location, linkRefs[]
    eventTime / dueTime: { value?, precision: dateTime|date, unconfirmed: bool }
    optional: bool
    unanalyzedAttachments: bool
  }
]
```

- 只有 `actionRequired` 和 `optionalEvent` 会生成候选事项；另外两类的 `items` 被忽略。
- 时间必须是带偏移的绝对时间或日期；相对日期由分析器根据收件时间和时区换算，做不到就标 `unconfirmed`。
- 提示词明确说明：邮件内容是不可信数据，其中的任何指令都不执行；签名里的地址不是活动地点；引用的旧邮件不是最新要求。

**有类型的失败**：

| 失败 | 处理 |
|---|---|
| 未安装 Claude Code | 不自动重试；状态栏提示请设置者检查，不给安装步骤（Claude Code 由设置者装好；Claude 桌面 App 不能代替它）。可以点 [重试] |
| 未登录 | 不自动重试；提示她打开 Claude Code 登录。可以点 [重试] |
| 额度用完 | 等待后自动重试（运行期间大约每 30 分钟一次，从 App 启动算起，不从失败时算起；启动、导入新文件时也会重试） |
| 输出格式不对 | 自动重试，累计 3 次后标为 `failed`，可手动重试 |
| 其他临时错误（超时、进程异常、网络） | 自动重试 |

分析失败的邮件保持 `pending`，不标成完成。分析一次只进行一封，一封失败不影响其他邮件。

未安装、未登录时不自动重试的是这些邮件本身；之后新导入的邮件照常尝试（这时失败不用额度）。有一封分析成功，说明 Claude 已经能用了，因未安装、未登录、额度用完而等着的邮件都放回待分析。

### ClaudeCodeAnalyzer 的安全要求

- 调用官方 `claude` 命令行的非交互模式，**禁用全部工具**，工作目录是每次新建的空临时目录，用完删除。
- 邮件内容只通过标准输入传入，不放在命令行参数里，也不写入文件。
- 要求输出符合上面结构的 JSON；DailyNote 先校验再使用。
- 有超时（暂定 120 秒），超时后结束进程并按临时错误处理。
- DailyNote 不读取、不保存、不转发 Claude 的登录凭据，登录由用户在官方流程里完成。
- 具体用哪些命令行参数，要在阶段 2 开始前用当前版本的 Claude Code 文档逐一核实，并写进测试（见"待验证事项"）。

### 自动分析的限额

- 导入后自动分析 `pending` 的邮件，按收件时间从新到旧。
- 每个本地日最多自动分析 100 封；达到后暂停，栏顶部显示"今天的新邮件较多，已暂停自动分析"和 [继续分析]。[继续分析] 解除当天的暂停。
- [这封有用] 和手动重试不计入上限。
- 只有 Claude 给出了输出的分析才计入上限：成功和输出格式不对算（格式不对每试一次算一次），临时错误、额度用完、未安装、未登录不算。

### 候选事项、加入和忽略

- 栏里显示所有 `candidate` 事项：需要行动在前，可选活动在后；同类里按截止时间或活动时间从近到远，没有时间的排在最后。
- [加入]：默认放到今天；旁边的"改日期"可以选今天或以后的日子（不能选过去）。卡片标题是事项标题；备注依次是摘要、要做的事、地点、第一个链接（卡片上只显示第一行，和现在一样）；活动时间和截止时间带过去；颜色是默认色；位置按现有"新建卡片"的规则放在可见区域内。事项状态变成 `accepted` 并记下卡片 id。
- [忽略]：事项状态变成 `ignored`。
- "已过滤的邮件"列表里有三种条目：分类为仅供参考或低价值的邮件、被忽略的事项、`deferredOld` 和 `failed` 的邮件。每条显示主题、发件人、日期和理由，并有 [这封有用]（邮件）或 [恢复]（被忽略的事项，回到栏里）。
- 卡片和事项的关联：卡片完成、取消完成、删除、恢复、顺延都不改事项状态；卡片被永久删除时，事项的卡片 id 置空，并视为"已删除"。

### 更新建议的规则

分析结果里 `match` 是 `update(某事项)` 时：

| 那个事项现在的状态 | 处理 |
|---|---|
| `candidate` | 直接改写候选的对应字段，标上"已更新" |
| `accepted`，卡片在画布上且未完成 | 同一事项之前的 `pending` 建议一律变成 `superseded`（这封邮件和卡片现在的内容一致时也是，比如改期后又改回原时间）；有改动时再新建一条 `pending` 的更新建议 |
| `accepted`，卡片已完成、在回收站或已永久删除 | 新建一条候选事项，"相关事项"指向原事项，栏里注明"可能和已完成的《…》有关"（卡片在回收站或已永久删除时为"可能和已删除的《…》有关"） |
| `ignored` | 同上，注明"和你忽略过的《…》有关" |

- [采用]：只把建议里列出的字段写到卡片上（标题、备注里对应的部分、两个时间），在同一个事务里把建议标成 `applied`。
- [不用]：标成 `rejected`，不再显示；以后的邮件提出同一字段的同一个值也不再提示，提出不同的值照常提示。
- 新邮件和重新分析**从不直接修改已加入的卡片**。

### 界面

- **栏**：画布页右侧，宽度固定；可以收起，收起时页头显示带数字的"邮件事项"按钮。窗口窄于 840 时变成底部面板，由页头按钮打开。顶部是状态行（见下表），然后是候选事项，底部是"已过滤的邮件 (N)"。
- **状态行**：

| 状态 | 显示 |
|---|---|
| 没有设置文件夹 | 开始设置 → 打开向导（向导做好之前打开设置页） |
| 文件夹不存在或没有权限 | ❌ 找不到邮件文件夹 → [重新选择] |
| 有文件还在写入或同步 | ⏳ 有文件正在同步，稍后自动导入 |
| 正常 | ✅ 上次导入：今天 07:12 · 新邮件 5 封 |
| 有格式错误的文件 | ⚠ 文件 mail-…json 格式不对（已跳过） |
| 超过 2 天没有新文件（格式错误的文件不算） | ⚠ 已 2 天没有新导出文件，请检查 Power Automate 流程 |
| 可能有遗漏 | ⚠ 可能漏掉了一些邮件，请让设置者手动补读 |
| 分析暂停或失败 | ⏸ 已暂停自动分析 [继续] / ⚠ 找不到 Claude Code，请让设置者检查 [重试] / ⚠ Claude 未登录 [重试] / ⏳ Claude 额度已用完，稍后自动重试 / ⚠ N 封邮件分析失败 [重试] |

状态行下方常驻一行小字："这里只能说明电脑上收到了文件，不代表云端流程现在还在正常运行。"多个问题同时出现时，按上表从上到下取第一个显示，点开可以看到全部。"正常"一行只在没有任何问题时显示在状态行上，有问题时放在点开后的列表最后。

- **卡片**：标题下面多一行时间（有活动时间和截止时间时只显示截止时间，详情里两个都显示）；来自邮件的卡片右上角有小信封图标；有 `pending` 更新建议时卡片正下方出现紧贴卡片的黄色提示条和 [采用] / [不用]（卡片本身放不下）。
- **编辑对话框**：在标题和备注下面加"活动时间""截止时间"两行，每行可以选日期、可选时刻、可以清空，"待确认"的显示为 ⚠。来自邮件的卡片多一个"查看来源邮件"按钮。
- **向导**：四步，顺序为同意 → 选择文件夹（立即检查）→ 检查 Claude Code → 用内置示例邮件试分析。每一步都可以返回上一步；中途退出后下次从未完成的那一步继续。

### 日志与隐私

- 日志里只记录邮件的内部 id、文件名、状态和错误类型，不记录主题、发件人和正文。
- Claude 的原始输出只在校验失败时截取前 200 个字符写进日志，并去掉换行；不记录请求内容。
- 测试数据全部是虚构邮件，放在测试目录里。

### 离线规则（AC-39）

- DailyNote 自己仍然不包含网络代码，`test/release/offline_test.dart` 的守卫测试保持不变并继续通过。启动子进程不属于网络代码。
- 在 spec 0001 的"认证与安全"一节补充一句：Windows 版的邮件分析会调用本机的 Claude Code，由 Claude Code 自己联网；DailyNote 本身不联网。

### Power Automate 流程（阶段 3，给设置者的说明）

```
定时触发：每天 07:00 和 16:00，时区 Eastern Time
→ 获取电子邮件 (V3)：收件箱，Top = 200，不包含附件
→ 撰写：信封格式（mailbox 是流程里手动填写的变量，exportedAt = utcNow()）
→ OneDrive for Business 创建文件：mail-<utcNow 精确到秒>-<运行编号>.json
另有手动触发入口：同样的步骤，Top = 1000，用于断开后补读
```

- 每次都取最近 200 封，相邻两次大量重叠，靠 App 去重；不靠流程记录"上次读到哪里"。
- 文件名带时间和运行编号，不会覆盖还没导入的文件。
- 失败重试靠连接器自带的重试和下一次运行的重叠范围；长时间断开后用手动补读。
- 文件清理由 App 负责（见"导入规则"）。
- 交付物：仓库里的图文配置说明（主要）和一个干净的流程包（可选，不放进安装包）。说明的最后有验收步骤。配置说明见 `docs/setup/power-automate-export.md`。

## Testing Decisions

### 什么是好的测试

沿用 spec 0001 的标准：只测对外的行为，用真实依赖（内存 SQLite、真实的 service），时钟用假的；测试名用中文描述一个行为。新增两条：

- 外部来源只在**接口边界**上替换：`ExportSource` 在测试里用一个真实的临时目录（直接写文件进去），`MailAnalyzer` 用一个按脚本返回结果或失败的假分析器。不 mock 数据库，也不检查 SQL。
- 测试数据全部是虚构邮件，覆盖英文、中文、HTML、带引用、带签名、相对日期、没有 `internetMessageId` 等情况。

## Acceptance Criteria

> 编号用 `M-` 开头，和 spec 0001 的 AC 区分。标 🖐 的是手动检查。

### 阶段 1：手动导入 JSON → 邮件预览 → 去重 → 错误处理

- M-1：数据库从 v1 升级到 v2 后，所有已有的卡片、连线、历史记录、回收站里的卡片和 AppMeta（`schemaVersion` 除外）都和升级前一样；`offline_test` 和所有已有的测试照常通过。
- M-2：卡片可以设置、修改、清空活动时间和截止时间（日期加时刻、只有日期、待确认三种），重新打开数据库后保持不变；顺延时这两个时间跟着卡片走，不影响顺延规则。
- M-3：卡片上的时间行按"只显示截止时间，没有截止时间才显示活动时间"的规则显示；只有日期时不显示时刻；待确认显示 ⚠；没有时间的卡片外观和以前完全一样。
- M-4：选择一个信封格式的 JSON 文件导入，所有邮件入库，并能在一个预览列表里看到主题、发件人和收件时间。
- M-5：裸数组格式的文件，在设置了邮箱地址时可以导入；没有设置邮箱地址时提示去设置页填写，不入库。
- M-6：同一个文件导入两次、内容相同但文件名不同的文件、与之前的文件有重叠的文件，都不会产生重复的邮件。
- M-7：缺少 `internetMessageId` 的邮件按 `id` 去重；两者都没有的邮件被跳过，同一文件的其他邮件正常入库。
- M-8：不是 JSON、`format` 不对、`version` 太新、`messages` 不是数组的文件，给出"格式错误"并指明文件名，数据库不变。
- M-9：导入事务中途失败时，数据库里没有这个文件的任何邮件，文件也没被标成已导入；再次导入能完整成功。
- M-10：HTML 正文被转成文本，链接被保留并编号；引用的旧邮件和签名被标记出来；`body` 为空时用 `bodyPreview`，并标记"正文可能不完整"。
- M-11：日志里没有邮件的主题、发件人和正文。
- M-12：Android 构建里看不到任何邮件入口。

### 阶段 2：Claude 分析 → 候选事项 → 加入画布 → 编辑和完成 → 更新建议

- M-13：新入库的邮件被自动分析；同一封邮件不会被分析两次（包括重复导入和重启之后）。
- M-14：分析器返回"需要行动"或"可选活动"时，生成对应数量的候选事项（0 个、1 个或多个都可以），出现在栏里，需要行动在前，可选活动带"可选"标签。
- M-15："仅供参考"和"低价值"不生成候选事项，出现在"已过滤的邮件"里，并显示理由。
- M-16：点 [加入] 后，今天的画布上出现一张卡片，标题、备注和时间来自事项，卡片带信封图标，事项从栏里消失；选"改日期"可以放到以后的某一天，不能选过去。
- M-17：[加入] 时新建卡片失败，事项仍然是候选，画布上没有新卡片。
- M-18：点 [忽略] 后事项从栏里消失，出现在"已过滤的邮件"里，可以 [恢复]。
- M-19：[这封有用] 会重新分析这封邮件并要求按需要行动处理，结果出现在栏里；这次分析不计入每日上限。
- M-20：分析失败的邮件保持待分析：额度用完和临时错误会自动重试；输出格式不对累计 3 次后标为失败，可以手动重试；未安装和未登录不自动重试，状态行给出对应提示和 [重试]；之后有一封新邮件分析成功，等着的邮件接着分析。
- M-21：首次设置时间之前 14 天以外的邮件不会被自动分析，在"已过滤的邮件"里能看到，可以点 [这封有用]。
- M-22：一天内自动分析到 100 封时暂停，状态行显示提示；点 [继续分析] 后继续；第二天自动恢复。
- M-23：分析结果引用了请求里没有的事项编号、时间无法解析或缺少必需字段时，按"输出格式不对"处理，不产生任何事项。
- M-24：后续邮件更新一个候选事项时，候选被直接改写并标"已更新"，栏里没有重复的事项。
- M-25：后续邮件更新一个已加入、未完成的卡片时，卡片上出现更新提示；在点 [采用] 之前卡片的内容不变；[采用] 只改提示里列出的字段；[不用] 之后提示消失且不再出现；同一张卡片只显示最新的一条建议。
- M-26：后续邮件涉及已完成、已删除或已忽略的事项时，栏里出现一条新候选并注明相关事项，原卡片不变。
- M-27：发给分析器的请求里没有收件人列表、完整邮件头和附件；"可能相关的现有事项"里只有编号、标题、时间和状态。
- M-28：`ClaudeCodeAnalyzer` 调用时禁用全部工具，在新建的空临时目录里运行，邮件内容只通过标准输入传入，用完删除临时目录，超时会结束进程。
- M-29：正文到期规则：有明确时间的保留到该时间之后 7 天；没有时间的保留 30 天；同一讨论有新邮件时顺延；卡片未完成或邮件待分析时不清除。清除后详情显示"原文已清理，请在 Outlook 中查看"，卡片和事项都还在。
- M-30 🖐：在开发电脑上用 10 封以上虚构邮件（包括相对日期、签名地址、引用旧邮件、写给 AI 的指令、只有图片的通知），真实调用 Claude Code，检查分类、时间、地点和"待确认"都合理，邮件里的指令没有被执行。

### 阶段 3：Power Automate 配置 → OneDrive 同步 → 自动导入 → 补处理和状态

- M-31：设置页可以用文件夹选择窗口选择文件夹，选完立刻检查并显示结果；路径只保存在本机数据库里；可以重新选择。
- M-32：App 启动时、运行期间每 5 分钟、点 [立即导入] 时都会扫描文件夹；只有 `mail-*.json` 会被读取。
- M-33：第一次看到的文件、大小或修改时间还在变化的文件不会被读取；解析失败且稳定不到 10 分钟的文件显示"正在同步"，超过 10 分钟显示"格式错误"。
- M-34：App 关着的时候同步过来的文件，下次启动时被导入和分析。
- M-35：状态行按"界面"一节的表格显示每种状态，并常驻"不代表云端流程正常"的说明。
- M-36：相邻两个满的文件之间有空档时，状态行提示"可能漏掉了一些邮件"。
- M-37：已导入、超过 14 天、没有待分析邮件的导出文件被删除；格式错误的文件不被删除。
- M-38 🖐：按配置说明在**她的** Power Automate 账号里建好流程，手动运行一次，OneDrive 里出现信封格式的新文件，并同步到她的电脑上。
- M-39 🖐：在她的账号上确认三个未验证的点：定时流程可以建立并按时运行；`Top = 200` 实际返回 200 封（邮件足够多时）；返回结果是最新的邮件在前。任何一条不成立时，回到本 spec 修改流程设计。
- M-40 🖐：向导四步在她的电脑上能走通，第 4 步用示例邮件试分析成功。

### 阶段 4：打包 Windows 版本，在她的电脑上按首次安装验收

- M-41：release 包里搜不到开发电脑的用户名、路径、测试邮箱、OneDrive 账号和任何凭据（自动检查打包目录里的字符串）。
- M-42 🖐：在她的电脑上解压 release zip，不装 Flutter 或任何开发工具，从向导开始走完：选择文件夹 → 检查 Claude Code → 试分析 → 等一次定时导入 → 加入一个事项 → 完成它。
- M-43 🖐：把邮件文件夹改个名字，状态行显示"找不到邮件文件夹"，重新选择后恢复正常。
- M-44 🖐：在她的电脑上走一遍 spec 0001 的主要功能，旧功能全部正常。

## Out of Scope

- Android、iOS 上的邮件功能；多设备同步邮件数据（以后接入同步时，邮件表整表不参与同步）。
- 多用户、多邮箱，或者做成给别人用的服务。
- Graph 直连、IMAP、读取经典版 Outlook 客户端（以后可以作为新的 `ExportSource` 加入）。
- Claude API 和其他 AI 服务（以后可以作为新的 `MailAnalyzer` 加入）。
- 下载或分析附件和内嵌图片。
- 改动 Outlook 里的任何东西：已读、移动、删除、回复、分类。
- 按时间排序的"事件簿"列表页和"待安排"分组。数据里已经有事项和时间，以后加列表页不需要迁移。
- 把卡片的截止时间做成提醒或系统通知。
- Ctrl+Z 撤销 [加入]、[忽略]、[采用]（需要撤销时删除卡片或从"已过滤的邮件"恢复）。
- App 关着的时候在后台分析邮件。
- 系统托盘、开机自启动。

### 建议的实施顺序

2. 导出文件解析和 HTML 转文本（纯函数）。
3. `MailService` 的导入和去重，加上手动选择文件和邮件预览（切入点 3 + 2）。→ 阶段 1 完成
4. Claude Code 验证任务（见"待验证事项"）。
5. `MailAnalyzer` 契约、结果校验、`ClaudeCodeAnalyzer`。
6. 分析队列和重试、候选事项、栏、加入和忽略、已过滤的邮件。
7. 更新建议、正文保留。→ 阶段 2 完成
8. 文件夹设置、定时扫描、状态行、导出文件清理、向导。
9. Power Automate 配置说明和流程包，在她的账号上验收。→ 阶段 3 完成
