# 卡片时间用一列文本存储，不用 UTC 毫秒整数

代码库的惯例是时间存 UTC 毫秒整数（见 `lib/storage/planner_database.dart` 开头），但卡片的活动时间和截止时间（schemaVersion 2）是例外：每个时间用"值、精度、待确认"三列，值是一列文本——精度为 `dateTime` 时存 UTC 的 ISO 8601 时间，精度为 `date` 时存本地的 `YYYY-MM-DD`（`DayKey`）。原因是"只有日期"是本地日历上的一天，不是某个时刻：如果换算成 UTC 毫秒，换时区或夏令时后会落到前一天或后一天；用一列文本可以把两种精度都原样存下，不需要额外的日期列。邮件表里的时间（spec 0002 说"和卡片上的结构一样"）也照这个格式存。

## Considered Options

- **毫秒整数列 + 单独的日期文本列**：和惯例一致，但每个时间要四列，而且两列里同时只有一列有值，读写都要多一种"两列都有值"的非法状态要处理。
- **只有日期时也存成本地零点的 UTC 毫秒**：列最少，但日期会随时区漂移，不可接受。

## Consequences

- 不要在 SQL 里对这一列排序或比较：两种精度的值混在同一列，`dateTime` 的文本长度也不固定（Dart 的 `toIso8601String` 在有微秒时会多出几位）。需要按时间排序或筛选时，读出来在 Dart 里比较。
- 以后改成别的格式需要一次数据迁移（重写已有的值），所以要在邮件表照抄这个结构之前定下来。
